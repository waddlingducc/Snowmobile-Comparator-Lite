SledSpec: deeper rework and release checklist

October 2, 2026 UTC · Evidence-based preparation, not a guarantee of AdSense approval.

Ready to upload; public deployment still pending. Direct checks found the public site still serving the earlier JavaScript-only content shells, old unsupported figures and “Verified specs” language. That is a confirmed local/live mismatch—not proof of Google's private rejection reasoning.

Substantive changes

  • Ownership-cost planner: your acquisition, fuel use, service, insurance, registration, transport/storage, financing interest and resale assumptions. Gross spending and net cost after resale are separate; depreciation is not counted twice.
  • Dealer-quote worksheet: compares itemized delivered prices, actual quoted tax amounts, trade-in credit, outstanding payoff and deposits. Trade equity and lower cash due are not mislabeled as savings. Both tools start blank, offer clearly hypothetical examples, validate inputs and let you print or download your work.
  • More useful comparisons: exact year/configuration, field-level price/weight/power caveats, source links and seller questions now appear alongside comparison values.
  • Deeper catalog evidence: full Arctic Cat manuals and a manufacturer-authored model-year booklet resolved multiple engine, track and estimated-weight gaps. The booklet's third-party hosting and regional conflicts are disclosed. Unmapped weights, unsupported horsepower and generic configurations remain uncertain.
  • All 23 model profiles reviewed: removed internal editing commentary and improved practical buyer implications, alternatives and seller checks without inventing ride tests.
  • Verifiable delivery: all static pages carry a content-derived release identifier. The ZIP includes a file-hash manifest; a read-only public-site checker detects stale content, partial uploads, missing assets, wrong metadata and false 404 responses.

Get this version onto the actual site

  1. Open your GitHub repository’s Settings → Pages → Build and deployment. Confirm the actual publishing branch/folder, or the artifact path in its GitHub Actions workflow. A ZIP upload elsewhere will not update the site.
  2. Extract the new sledspec-<release-id>.zip. Its root contains index.html, release.json, assets/, route folders, CNAME and hidden .nojekyll. Upload the contents to the confirmed publishing source—not the ZIP or a wrapper folder. Preserve source code and workflows outside that folder, and keep a rollback copy.
  3. Wait for the GitHub Pages deployment to finish. Open https://sledspec.com/release.json and compare its release ID with the ZIP's manifest. This is a quick identification check, not a substitute for full verification.
  4. Run pnpm run preflight:live from the snowmobile app directory, or have the agent run it. It checks the public files against the completed local release and writes a report. A successful build, screenshot or uploaded ZIP does not prove publication.
  5. Check the real domain on mobile, including the buying tools, comparison, a direct model link, an article with JavaScript disabled, and an invalid address. Only request another AdSense review after confirming the intended version is public and addressing other issues in the actual rejection notice.

Evidence only the owner can supply

  • The latest rejection text/screenshot, review date and reviewed URL. No new notice was provided during this work.
  • A publishable operator identity and actual editorial credentials, if any. None were invented.
  • Confirmation the listed mailbox is owned, receives messages and is monitored. No delivery test or response promise was fabricated.
  • Source and permission records for the 23 retained reference photographs. The inventory records their file hashes, but hashing does not establish copyright permission. No photographs were deleted or replaced without authorization.
  • Actual AdSense ownership/account setup, ads.txt publisher authorization and privacy/consent configuration before enabling advertising. There are no ad-serving scripts enabled by this build.

What the policy research supports

Google’s site-readiness guidance asks for original value and useful navigation. Low-value inventory policy is not satisfied by padding pages. Search helpful-content guidance supports useful, accurate analysis and honest authorship but is not an AdSense checklist or word-count requirement. Privacy disclosures and certified consent-management requirements depend on the actual advertising setup and applicable regions. No universal traffic target or waiting period is invented here.

TypeScript checks, 11 calculation tests and four release-validation fixture suites passed.
